# Preregistration: Phase 1 (Boot)

- **Registered:** 2026-10-18. Registered before any fidelity-suite comparison, any formal exact-tier run and any GPU run. The commit that adds this file is the registration record.
- **Status:** frozen. Do not edit this file after its runs. Changes go in dated amendments at the end.
- **Design:** [`PHASE1_ENGINE_PROPOSAL.md`](PHASE1_ENGINE_PROPOSAL.md), approved by the maintainer on 2026-10-18.

## Claim under test

> The ASCEND engine simulates the full FlyWire v783 connectome-constrained model (138,639 neurons, 15,091,983 connections, dt = 0.1 ms) at real-time factor ≥ 1.0 on one consumer NVIDIA GPU, fidelity-matched to the Shiu et al. 2024 reference model.

The claim is earned only if every rule in the claim rule below passes. Each part is reported separately, misses included.

## Engine (fixed for these tests)

- **Code:** `ascend/engine/`:
  - `cpu.py` is the NumPy engine.
  - `kernels.cu` holds the GPU kernels.
  - `cuda.py` and `kernel_engine.py` are the CUDA host code, using CuPy, NVRTC and one CUDA Graph per 1,000-step chunk.
  - `emulate.py` runs the same kernels on the CPU for tests.
- **Model:** the model and constants come from the vendored reference (`ascend/engine/params.py`). The per-step order follows Brian2's schedule for the reference network:
  1. state update;
  2. threshold;
  3. delayed synaptic delivery and stimulus, both applied only to non-refractory targets;
  4. reset.
- **Stimulus:** each stimulated neuron receives a kick of `w_poi` = 68.75 mV with probability rate × dt per step. Kicks come from a counter-based hash of (seed, step, neuron) (`ascend/engine/rng.py`), which is identical on every backend. They are not Brian2's random stream, so the GPU engine can only be compared with the reference statistically.
- **Precision:** CPU defaults to float64 and CUDA to float32. On the GPU, the order of `atomicAdd` into `g` is not deterministic, so GPU runs are reproducible only statistically.

## E: exact tier (build VM, CPU)

`scripts/exact_check.py` draws Bernoulli(150 Hz × dt) kicks with NumPy seed 0. It feeds the identical kicks to the Brian2 reference network (`run_events`: upstream `create_model()`/`poi()`, kicks delivered in PoissonInput's schedule slot with the same gating) and to the ASCEND CPU engine in float64. It then compares every spike over 1.0 s (10,000 steps).

| Workload | Stimulus | Reference target |
|---|---|---|
| E-sugar | 21 sugar GRNs | Brian2 Cython |
| E-bitter | 21 bitter GRNs | Brian2 Cython |
| E-jon | 146 JONs | Brian2 Cython |
| E-none | none | Brian2 Cython |

**Pass:** spike trains are identical (same neurons, same time steps) in all 4 workloads.

## F: statistical fidelity tier

`ascend/fidelity.py` runs, for each reference condition, 30 one-second trials (seeds 0–29, the engine's own stimulus stream). It compares them with `results/phase0/reference_rates.json`:

| Condition | Stimulus |
|---|---|
| `v783_sugar_150hz` | sugar GRNs, 150 Hz |
| `v783_bitter_150hz` | bitter GRNs, 150 Hz |
| `v783_jon_all_150hz` | all JONs, 150 Hz |
| `v783_none` | none |

Rates are counts / 1 s. Means and SDs are taken over trials (ddof = 0). SE = √(SD_engine²/30 + SD_ref²/30). Checks per condition:

- **F1** (no stimulus only): zero spikes in every trial.
- **F2:** each readout neuron with reference mean ≥ 1 Hz (MN9 × 2 under sugar; DNg62 and DNge078 under JONs) satisfies |Δmean| ≤ 4·SE + 0.5 Hz.
- **F3:** among neurons with mean ≥ 1 Hz in the reference or the engine, at most 1 % violate |Δmean| ≤ 4·SE + 0.5 Hz.
- **F4:** Pearson r between engine and reference mean rates, over all neurons active in either, is ≥ 0.99.
- **F5:** mean total spikes per trial satisfies |Δ| ≤ 4·SE_total + 1 % of the reference mean.

**Pass:** every check in every condition. A test (`tests/test_fidelity.py`) pins these thresholds.

### Controls on the build VM (CPU engine, `scripts/fidelity_check.py`)

| Run | Engine | Expected | Role |
|---|---|---|---|
| F-pos | CPU float64, as built | **pass** | Positive control: the exact engine with a different random stream must pass. |
| F-f32 | CPU float32, as built | pass (reported) | Same arithmetic precision as the GPU. A failure predicts GPU failures. |
| F-neg-delay | CPU float64, synaptic delay 17 steps instead of 18 | **fail** | Negative control |
| F-neg-weight | CPU float64, all weights × 0.95 | **fail** | Negative control |

If F-pos fails, or either negative control passes, the F tier is declared inadequate. The real-time claim then cannot be made until a dated amendment fixes the tier, and that amendment is reported as a miss.

## S: speed tier (consumer GPU)

- **Workload:** `scripts/bench.py --engine ascend --device cuda` defaults. That is v783, 21 sugar GRNs at 150 Hz, 1.0 s per trial, 5 trials with seeds 0–4, CUDA float32.
- **Timing:** each trial resets the engine and times `run()` (wall clock, including chunk read-back). Network build and the untimed warm-up (NVRTC compile, graph capture) are excluded. This is the same definition as Phase 0.
- **S1:** median RTF ≥ 1.0.
- **Consumer GPU:** an NVIDIA GeForce or TITAN card, desktop or laptop. Data-centre (e.g. A100, H100, L4, T4, V100) and professional workstation (RTX A-series, RTX Ada-series) cards don't count, though their results are published.
- **Valid submission:** run on an unmodified checkout (`repo.dirty = false`), with `valid_submission = true`, posted through the Benchmark result issue template with the full JSON.

## Claim rule

The real-time claim is earned when all four hold:

1. **E** passes on the build VM.
2. **F-pos** passes, and both negative controls fail, on the build VM.
3. A consumer-GPU submission of `python scripts/bench.py --engine ascend --device cuda --fidelity` shows `S1_rtf_median_ge_1: true` and `F_fidelity_suite: true` in the same JSON.
4. An independent reproduction does the same: a second submission meeting rule 3, from a different person, on a different GPU model.

Then, and only with the maintainer's approval, the README may state the measured RTF together with its hardware.

## Predictions (not criteria)

- E: identical in all 4 workloads.
- F-pos and F-f32 pass; both negative controls fail.
- GPU RTF of about 7–15 on a mid-range consumer GPU (RTX 3060 / 4060 / 4070 class), with a conservative expectation of RTF ≥ 3 on an RTX 3060-class card (arithmetic in the design doc).

## Pilots disclosed

These ran while building the engine, before this registration. None is a result:

- **Synthetic exact-tier checks:** CPU float64 vs Brian2 numpy and Cython targets on 300–2,000-neuron random networks gave identical spikes (up to 93,892 spikes).
- **Full brain, 0.2 s:** CPU float64 vs Brian2 Cython with sugar kicks gave identical spikes (2,689 spikes, 347 neurons).
- **Emulated kernels vs CPU engine:** identical spikes on synthetic networks in float64 and float32.
- **NVRTC compile** of `kernels.cu` for compute 6.0–8.9 succeeded in float and double. No GPU was available.
- **CPU engine timing:** a 0.2 s sugar run on the full brain gave RTF 0.056 (float64) and 0.097 (float32).
- **What has not been run:** any fidelity-suite comparison with the reference rates, any 1 s full-brain exact check, and any GPU execution.
